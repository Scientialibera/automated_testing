# LLM Evaluation Experiments

Collection of evaluation experiments for generative AI applications. The repository covers prompt testing, generation checks, retrieval evaluation, classification experiments and answer-quality metrics. It is an experimental evaluation workspace, not a deployable service.

## Repository layout

| Path | Purpose |
| --- | --- |
| `Classification.ipynb` | Classification experiment |
| `Generation/` | Generation test notebooks and sample inputs |
| `Prompt_Testing/` | Prompt comparison experiments |
| `Retrieval/` | Retrieval accuracy experiments |
| `Metrics/` | Rated answers, prompts and similarity analysis |
| `Classes/` | Shared/legacy Azure Search helper material |

The CSV/XLSX files under `Metrics/` are evaluation fixtures and results. Keep production data, customer prompts and sensitive documents out of this repository.

## Local setup

```bash
python -m venv .venv

# Windows
.venv\Scripts\activate

# macOS/Linux
source .venv/bin/activate

pip install -r requirements.txt
cp .env.example .env
jupyter lab
```

Use Microsoft Entra ID / managed identity for Azure services when possible. Local `.env` files are ignored and must not be committed.

## Evaluation conventions

For repeatable comparisons, record at minimum:

- model/deployment identifier
- prompt or prompt version
- retrieval configuration and top-k
- evaluation dataset version
- random seed where applicable
- scoring method and threshold
- execution date

Do not compare model or prompt variants using different test sets unless the difference is intentional and documented. Separate automated metrics from human ratings; neither should be treated as a complete measure of application quality on its own.

## Historical code

Some notebooks and the helper under `Classes/` were written against older Azure/OpenAI SDK versions. They are retained as research material. New production code should use current SDK APIs and be moved into a package with tests rather than expanding notebook utility code.

## Repository hygiene

The previous repository contained a tracked `environment.env` template and compiled Python bytecode. Those artifacts are removed in the hardening branch. Real credentials, local environment files, caches and generated bytecode are excluded by `.gitignore`.

No CI/CD configuration is included. This repository is intended for controlled local evaluation and reproducible experiments.
